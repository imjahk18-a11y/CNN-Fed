# STPLS3D 전체 Synthetic 데이터 복원 공간 점검

**2026-11-18 linuxserver2에서 다운로드 전 중단했다.** 63개 중 기존 원본 4개를 검증했다. 새 다운로드는 0/59개, 네트워크 전송량은 0바이트다. 잔여 원본을 보관하면 사용자 quota에 7.17 GiB만 남아 사용자 지정 최소 여유 8 GiB를 충족할 수 없다.

기존 배포 ZIP의 중앙 디렉터리 기록과 inventory에서 경로·크기·중복 여부를 대조했다. 38개 및 23.86 GB는 v1과 v2의 소계다. 전체 대상은 Synthetic 폴더의 PLY로 한정했다. WMSC는 외부 평가용으로 이미 확보되어 있다. 기존 v3의 3·4·12·13번 장면에서 실제 확보한 원본은 **1,424,849,486바이트**다. PLY를 다시 읽어 파일 크기, ZIP 멤버 CRC-32, 이전 확보 때 기록한 SHA-256 모두 일치함을 확인했다. [63개 파일 목록과 상태](download_manifest.csv) · [무결성 기록](download_integrity.json)

같은 파일시스템 내 rename 방식은 검증 중인 .partial을 최종 파일로 옮겨 한 파일 분량의 중복을 피한다. 전체 ZIP 보관은 예산에서 제외했다. 이 조건에서도 원본만 확보하고 8 GiB를 남기려면 시작 시점보다 최소 **0.83 GiB** 더 필요하다. 현재 Full-Z 캐시 형식과 관측한 큰 캐시 비율을 적용하면 전체 사용자 quota 추정치는 **60.31 GiB**다. v1·v2의 점유 밀도와 실제 캐시 크기는 확보 후 다시 측정해야 한다. 캐시 압축률과 관계없이 원본 단독에서 이미 중단 조건이 성립한다. 두 quota 측정값은 사용자 계정 전체 기준이다. ## 전체 데이터에 의존하는 단계

새로 확보한 장면이 없어 전체 장면 통계·클래스 누락·기존 v3와의 차이는 아직 측정할 수 없다. 이번 실행에서 생성한 캐시는 0바이트다. 과거 목표는 train 145,329패치와 validation 37,837패치다. 전체 split이 없어 실제 train/validation 수와 목표 대비 차이, 공간 중복, 누수, 시드는 미정이다. 기존 네 장면의 10,816패치는 확보량 집계다. [Split 상태](train_val_split.json)

전체 split 기반 batch 24 DataLoader, RTX A6000 forward/backward 및 GPU 메모리 측정은 미실행이다. 이번 실행의 optimizer step은 0회다. [GPU 점검 상태](gpu_dataloader_smoke.json)

**다음 35 epoch 학습 명령은 미확정이다.** 현재 프로젝트의 sparse 실험 진입점은 장면 13 학습·12 검증을 고정해 둔다. 전체 복원 후 확정된 split을 읽는 로더로 batch 24 검증을 통과해야 전체 데이터용 학습 명령을 확정할 수 있다.
